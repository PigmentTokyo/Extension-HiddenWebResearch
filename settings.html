Hidden Web Research / 隐藏联网研究
自动判断是否搜索；当前公开版仅使用原版 SillyTavern 自带的 SearXNG 与 SerpAPI 路由。搜索结果可作为本轮临时工具结果或隐藏研究包进入模型，两种方式都不会生成聊天楼层、附件或 Data Bank 文件。
这里决定三件事：模糊场景如何判断是否值得搜索、怎样组织与补充查询、当前模型最后怎样使用证据回答；它不是联网总开关，也不会把当前模型替换成 Claude 或 Gemini，更不会调用厂商官方搜索服务。 Claude 启发先判断外部证据是否真正必要，再逐个查证缺口并克制引用；Gemini 启发先判断搜索能否改善正确性、时效性或可验证性，再把信息需求提炼成高意图查询并逐段 Grounding。 DeepSeek V4 Pro、GLM 5.2 与 Kimi K3 分别强调分面合并、层级核验与研究收敛。策略推荐总查询数分别为 Claude 3、Gemini 4、V4 Pro 4、GLM 5.2 4、Kimi K3 3、通用 3；它们只是经济性建议，实际每轮与总查询硬上限完全由“高级限制”中的数值决定。
自定义查询规划与最终回答策略
这是所选内置策略之上的补充层，同时影响隐藏规划器怎样组织查询，以及搜后怎样使用证据回答；不会替换当前模型，也不会调用所选名称对应的厂商模型。 例如当前回答模型是 DeepSeek 而手选 Claude，仍由 DeepSeek 执行，只是采用 Claude 启发的规则与这份补充指令。

自动模式会在酒馆确认当前连接支持函数调用时，把已完成的搜索重构为仅本轮请求可见的 hwr_web_search 工具调用与工具结果；Claude、Gemini 与 OpenAI 兼容来源会由酒馆转换为各自的普通客户端工具协议。 本轮只综合已有结果，不再开放其他函数工具，也会强制关闭厂商原生联网搜索，避免重复搜索和测试污染。 若函数调用关闭、消息协议不兼容或无法安全定位本轮研究内容，会保留隐藏研究包。 当前酒馆的 Gemini 3 转换器不会回传函数调用 ID，因此 Gemini 3 专用来源会保守使用隐藏研究包。
自动兼容回退发生在请求发送前；若某个中转错误宣称支持工具、但上游发送后才返回协议错误，前端扩展无法在同一轮透明重发。 遇到这种渠道时请选择“固定使用隐藏研究包”。
触发策略回答“这一轮是否进入研究流程”。“模型自动判断”会调用当前回答模型作为隐藏规划器：明确搜索、天气、时效信息和推荐等高置信场景由本地门控保证至少搜索一次，其余模糊场景由上面的模型策略判断；即使最后不搜索也会消耗规划 tokens。 “每条消息”仍会让规划器先组织查询，但至少执行一次搜索；明确禁止联网和只问本机日期/时间是例外。“仅明确要求联网”会在其他消息上本地零 token 跳过。当前用户明确要求“不联网”始终优先于全部选项。
自定义触发判断提示词
只补充隐藏规划器对模糊场景的 SEARCH / DONE 判断，不会改写本地门控：明确“不联网”仍最高优先；“每条消息”和高置信动态场景的首次搜索不能被取消；“仅明确要求联网”未命中时根本不会调用规划器。

SearXNG

当前 SearXNG 路径只使用搜索结果标题、URL、日期和摘要，不会像原生搜索工具那样继续读取完整网页；它属于摘要级研究。

SerpAPI Google Search

复用原版 SillyTavern 内置的 SerpAPI 密钥槽与基础搜索路由。这里保存的新 Key 也会成为酒馆 WebSearch 等功能使用的当前共享 Key；每次只请求一页。
高级限制
复用时间适用于当前启用的 SearXNG 与基础 SerpAPI 隐藏研究。
“规划器 tokens”是通用下限；模型专属提示策略会覆盖较小值：DeepSeek V4 Pro 1024、GLM 5.2 1536、Kimi K3 2048。私有 hwr_planner_profile 服务端标记当前暂停；普通请求参数是否生效由原版酒馆和上游决定。
“每轮最多查询”“总查询上限”和“最多规划轮数”是实际执行硬上限；模型策略中的数量只是推荐，不会再暗中压低你填写的数值。
