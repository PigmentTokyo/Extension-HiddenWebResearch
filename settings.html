Hidden Web Research / 隐藏联网研究
自动判断是否搜索；SearXNG、AnySearch、SerpAPI 与 Claude 在后台研究，Gemini 原生模式直接给出唯一最终回答。所有密钥都由 SillyTavern 服务端保管。不会生成工具楼层、附件或 Data Bank 文件。
除 Claude/Gemini 启发策略外，1.4.0 只为当前旗舰 DeepSeek V4 Pro、GLM 5.2 与 Kimi K3 建立专属档案：V4 Pro 合并同一主管机关下的相关分面，GLM 5.2 按主管层级与统计口径核验，Kimi K3 强制收敛其 Deep Research 式扩张。硬查询帽分别为 Claude 3、Gemini 4、V4 Pro 4、GLM 5.2 4、Kimi K3 3、通用 3。旧型号不会冒充这些新档案。
Claude 与 Gemini 都先在本地判断；跳过的消息不会调用研究模型。明确要求“不联网”始终优先。

SearXNG

当前 SearXNG 路径只使用搜索结果标题、URL、日期和摘要，不会像原生搜索工具那样继续读取完整网页；它属于摘要级研究。

AnySearch（anysearch.com）

使用 AnySearch 官方统一搜索 REST API。Key 可选；不保存 Key 时使用匿名额度。返回的正文或摘要会受本扩展的证据字符预算约束，不会原样写入聊天记录。

SerpAPI Google Search

复用 SillyTavern 内置的 SerpAPI 密钥槽与搜索路由。这里保存的新 Key 也会成为酒馆 WebSearch 等功能使用的当前 SerpAPI Key；每次只请求一页，不自动翻页放大费用。

Claude 原生搜索桥接

该模式由一个独立 Claude 连接（Connection Profile 或下方直连）执行 Anthropic web_search，再把研究结果临时交给当前主模型。来源支持时使用官方最新 web_search_20260318，并强制 direct 模式，以便稳定提取结构化搜索结果；不支持该协议的中转无法由扩展补齐。只有通过本地门控时才产生 Claude token 与搜索费用。
URL 与 Key 会绑定成一个凭据包保存到 SillyTavern 服务端 secrets；扩展设置只保存 URL 与模型名。实际请求不能临时改发到其他地址。
填写到 API 根路径；若粘贴了末尾 /messages，保存时会自动去除。中转必须兼容 Anthropic Messages 和原生 web_search 内容块。
尚未拉取模型列表；也可以始终手工填写精确模型 ID。

Gemini 原生搜索直答

通过本地门控后，由所选 Gemini Profile 或下方直连执行 Google Search，并把 Gemini 的完整 grounded answer 直接作为本轮唯一助手回复；当前主模型本轮不会调用。官方引用和 Google Search Suggestions 会同屏显示，且不会进入隐藏研究缓存。受 Google 展示与使用条款约束，Grounded Result 不能先隐藏，再交给 Claude、DeepSeek 或其他模型转写。
直连只支持 Google AI Studio generateContent 协议；Vertex AI 请继续使用 Profile。URL 与 Key 会绑定保存到 SillyTavern 服务端 secrets。
不要填写 /v1、/v1beta 或 /models/...；末尾版本路径会在保存时自动去除。
尚未拉取模型列表；也可以始终手工填写精确模型 ID。
推荐 Gemini 2.5 Flash-Lite + 1024–2048；Gemini 3 的隐藏思考可能需要 8192 或更高，并可能自动执行多条计费搜索查询。
gcli 兼容配置：可在 Connection Manager 建立 Google AI Studio Profile，也可直接在上方保存站点根地址（例如 https://gcli.ggchan.dev，不要保留 /v1）与对应 Key；模型可选 gemini-2.5-flash-lite。不要选 OpenAI 包装的 -search 型号，否则拿不到结构化 Grounding 与 Search Suggestions。
此模式不提供后台“测试搜索”：实际搜索结果必须展示给发起用户。可发送一条“请联网查……”消息进行验证。
高级限制
复用时间适用于 SearXNG、AnySearch、SerpAPI 与 Claude 隐藏研究；Gemini 原生最终回答始终重新请求，不缓存 Grounded Result。
“规划器 tokens”是通用下限；模型专属安全下限会自动覆盖较小值：DeepSeek V4 Pro 1024、GLM 5.2 1536、Kimi K3 2048。Kimi K3 始终思考，因此规划延迟通常更高。
